### Known defects in the legacy `garmin_mcp_server.py` that MUST NOT be carried over

1. `get_daily_steps(d)` — called with 1 arg, needs 2. Wrapped in `except Exception: pass`, so it
   silently reports nothing. There are **eight** such silent-swallow blocks in `get_health_summary`.
2. `delete_plan_workouts(name_contains="")` deletes **every workout in the account** by default.
3. `garmin_retry` returns the string `"Error after N attempts: ..."` — a failure rendered as a
   successful tool result. Errors must surface as protocol errors.
4. The retry decorator wraps `push_workout`, so a failed-but-partially-applied create is retried.
5. `time_condition`/`distance_condition` are annotated `-> dict` but return `tuple`.
6. `pace_to_ms` crashes with an unhandled `ValueError` on any malformed pace string.
7. `push_training_plan` calls the *decorated* `push_workout`, stacking retry inside retry.
8. Bare `except Exception` around token save; credentials interpolated into log lines.

### `config.py` (owner P3)

```python
DEFAULT_TOKEN_DIR = "~/.garmin-coach-mcp/tokens"

@dataclass(frozen=True)
class Settings:
    email: str | None
    password: str | None
    token_dir: Path            # expanded, absolute
    read_only: bool            # when True, write tools are not registered
    request_timeout: float
    max_retries: int
    log_level: str

    @classmethod
    def from_env(cls, env: Mapping[str, str] | None = None, **overrides) -> "Settings": ...
```

Env vars: `GARMIN_EMAIL`, `GARMIN_PASSWORD`, `GARMIN_TOKEN_DIR`, `GARMIN_READ_ONLY`,
`GARMIN_REQUEST_TIMEOUT`, `GARMIN_MAX_RETRIES`, `GARMIN_LOG_LEVEL`.
`GARTH_TOKEN_DIR` stays supported as a deprecated alias for `GARMIN_TOKEN_DIR`.

### `errors.py` (owner P3)

```python
class GarminMCPError(Exception):
    def __init__(self, message: str, *, remediation: str | None = None,
                 cause: BaseException | None = None) -> None: ...
    message: str
    remediation: str | None
    def to_tool_error(self) -> ToolError:   # mcp.server.fastmcp.exceptions.ToolError
        """Message + remediation, formatted for an LLM to act on."""

class ConfigurationError(GarminMCPError): ...    # missing/invalid settings
class AuthenticationError(GarminMCPError): ...   # bad credentials, expired token, MFA
class RateLimitError(GarminMCPError): ...        # HTTP 429
class UpstreamServiceError(GarminMCPError): ...  # Garmin 5xx, network, timeout
class NotFoundError(GarminMCPError): ...         # unknown activity/workout id
class InvalidRequestError(GarminMCPError): ...   # semantic input error past schema validation
class ReadOnlyModeError(GarminMCPError): ...     # write attempted in read-only mode
```

Every raised error MUST carry a `remediation` that tells the caller what to do next.
No bare `Exception`. No returning error strings from tools — raise.

## Tool surface (owner P2)

Reference-server conventions that are mandatory:

- Every tool gets `title`, a precise description, and `annotations`
  (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`).
- Every parameter is a typed pydantic field with `Field(description=...)` and, where
  applicable, `ge`/`le`/`min_length`/`pattern` constraints. Enums, not free strings.
- **No JSON-encoded-string parameters.** `steps_json` / `workouts_json` must become real
  nested pydantic models so the schema is self-documenting and the client validates input.
- Tools return structured content (pydantic models) — FastMCP derives the output schema.
  Keep a readable text rendering alongside for human-facing clients.
- Destructive tools (`delete_*`) must be explicit and narrow. A bulk delete that defaults to
  deleting *everything* when given an empty argument is a defect, not a feature.
- Dates: ISO `YYYY-MM-DD`, validated. Accept `date` objects.

## Behavioural rules

- Never log credentials, tokens, or full auth payloads.
- All logging goes to **stderr** (stdout is the stdio transport channel).
- Retry only idempotent reads and explicitly safe writes; never blind-retry a create.
- No `except Exception: pass`. Ever.
